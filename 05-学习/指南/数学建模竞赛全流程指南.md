## 赛前知识体系

数学建模竞赛的核心能力三层：

```
         ┌──────────────┐
         │  论文写作     │ ← 评审唯一看到的，占 70% 分数
         ├──────────────┤
         │  模型构建     │ ← 核心思路，占 20% 分数
         ├──────────────┤
         │  编程实现     │ ← 支撑工具，占 10% 分数
         └──────────────┘
```

一个残酷的事实：**评审看一篇论文的平均时间是 5-8 分钟。** 如果你的摘要没抓住他，后面写得多好都没用。

## 建模篇

### 常见模型速查

#### 评价类问题
> 题干关键词：评价、排名、分级、选择最优方案

| 模型 | 适用场景 | 输入 | 输出 |
|------|---------|------|------|
| 层次分析法（AHP） | 多因素主观评价，因素不超过 9 个 | 专家打分 | 各方案综合得分 |
| TOPSIS | 客观数据评价，有多个指标 | 原始数据矩阵 | 各方案贴近度排序 |
| 熵权法 | 确定各指标的客观权重 | 原始数据 | 各指标权重 |
| 模糊综合评价 | 定性指标多，难以精确量化 | 隶属度函数 + 权重 | 综合评价等级 |
| 灰色关联分析 | 小样本、信息不完全 | 参考序列 + 比较序列 | 关联度排序 |

**组合拳**：熵权法确定权重 + TOPSIS 排序（最常用的组合）
**避雷**：AHP 别用在超过 9 个指标的场景，评审会直接扣分

#### 预测类问题
> 题干关键词：预测、趋势、未来、随时间变化

| 模型 | 适用场景 | 数据要求 |
|------|---------|---------|
| 灰色预测 GM(1,1) | 小样本（4-10 个点）、指数增长 | 少 |
| 时间序列 ARIMA | 平稳时间序列，数据量 > 30 | 中 |
| 线性/非线性回归 | 有明确影响因素 | 中 |
| 神经网络（BP/LSTM） | 复杂非线性关系，数据量大 | 多 |
| 指数平滑 | 有季节性/趋势性的短期预测 | 中 |

**避雷**：不要拿到数据就上神经网络。评审更喜欢"简单模型 + 深刻分析"而非"复杂模型 + 空洞解释"。

#### 优化类问题
> 题干关键词：最优、最大/最小、分配、调度、路径

| 模型 | 适用场景 |
|------|---------|
| 线性规划 / 整数规划 | 目标函数和约束都是线性的 |
| 非线性规划 | 目标函数或约束非线性 |
| 多目标规划 | 多个冲突目标需要权衡 |
| 动态规划 | 多阶段决策问题 |
| 图论模型（最短路径、网络流） | 路径、配送、网络优化 |
| 遗传算法 / 粒子群 / 模拟退火 | 复杂 NP-hard 问题，求近似解 |
| 蒙特卡洛模拟 | 随机因素大的优化问题 |

**避雷**：除非数据量极大，优先用精确算法（线性规划求解器），别一上来就遗传算法。评审看到"用遗传算法求解一个线性规划问题"会觉得你不懂模型选择。

#### 统计/数据分析类
> 题干关键词：相关性、差异、显著、因素分析

| 模型 | 适用场景 |
|------|---------|
| 描述性统计 | 任何数据题的第一步 |
| 相关性分析（Pearson/Spearman） | 两变量关系 |
| 回归分析（多元线性、Logistic） | 多因素影响分析 |
| 聚类分析（K-means、层次聚类） | 无监督分类 |
| 判别分析 | 有标签的分类问题 |
| 主成分分析（PCA） | 降维、去多重共线性 |
| 假设检验（t检验、卡方检验） | 判断差异是否显著 |

### 选题策略

数学建模国赛三道题大致规律：

| 题号 | 特点 | 适合 |
|------|------|------|
| **A 题** | 物理/工程类，有明确物理背景，模型选择范围窄 | 数学/物理底子好 |
| **B 题** | 数据/优化类，偏 CS，近年越来越偏 AI | **你最适合** |
| **C 题** | 经管/社科类，数据开放，门槛低，竞争最激烈 | 慎选（卷） |

**选题铁律**：
1. 三人都要能看懂题目——不要硬选"看起来高端的"
2. 先看数据——拿到数据先跑一遍描述性统计，数据不对立刻换题
3. B 题是你最好的选择——AI 背景 + Python 能力 + Kaggle 建模经验是天配
4. 2 小时内必须定题。摇摆超过 3 小时的队基本都拿不到好名次

### 代码规范（对评审很重要）

```python
# ✅ 好代码：有清晰注释 + 可复现
# 数据标准化（Z-score）
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
data_scaled = scaler.fit_transform(raw_data)

# ❌ 坏代码：无注释，变量名无意义
x = (a - a.mean()) / a.std()
```

**要求**：
- 提交的代码放在附录里，每段核心代码要有注释
- 随机种子固定（`np.random.seed(42)`），确保结果可复现
- 不要贴全量代码——附录放关键算法即可，正文只需伪代码或流程图

### 论文插图标准

这是评审第一眼看到的东西。一张好的图比一千字论证更有说服力。

| 图的类型 | 适用场景 | 工具 |
|----------|---------|------|
| 折线图 | 趋势、预测对比 | matplotlib |
| 柱状图 | 分组对比 | matplotlib / seaborn |
| 散点图 | 相关性、聚类结果 | matplotlib / seaborn |
| 热力图 | 相关性矩阵、空间分布 | seaborn heatmap |
| 箱线图 | 数据分布、离群值 | seaborn boxplot |
| 流程图 | 模型框架、算法步骤 | draw.io / PPT |
| 思维导图 | 问题分解、因素分析 | draw.io / XMind |

**制图铁律**：
1. 所有图必须**矢量格式**（PDF/SVG），不要用 PNG/JPG
2. 中文字体设 SimHei，英文 Times New Roman，字号统一
3. 配色不要用默认的蓝橙，用 seaborn 的色板或者手动调
4. 流程图和模型框架图**必须自己画**，这是 AI 做不出来的东西
5. 每张图下面要有图注，说明"这张图告诉读者什么"

## 写作篇

### 论文结构（国赛标准）

| 章节 | 内容 | 篇幅 | 谁写 |
|------|------|------|------|
| **摘要** | 问题→方法→结果→结论，一句话概括每个环节 | 1页，约800字 | 三个人一起写 |
| 问题重述 | 用自己的话把题目复述一遍 | 半页 | 写作手 |
| 问题分析 | 拆解问题，提出解决思路 | 半页 | 建模手 |
| 模型假设 | 列出所有假设条件 | 5-8条 | 建模手 |
| 符号说明 | 表格形式，文中所有符号的定义 | 半页 | 写作手 |
| 模型建立与求解 | 核心章节，每个问题一个子章节 | 8-15页 | 建模手+写作手 |
| 模型检验 | 灵敏度分析、误差分析、对比验证 | 2-3页 | 建模手+编程手 |
| 模型评价与改进 | 优点、缺点、改进方向 | 半页 | 建模手 |
| 参考文献 | 10-15篇 | 半页 | 写作手 |
| 附录 | 核心代码、数据表格 | 不限 | 编程手 |

### 摘要怎么写

摘要是评审**决定要不要继续读**的唯一理由。它必须独立成文——评审不看正文也应该能理解你做了什么。

模板：

```
针对[问题背景]，本文建立了[模型名称]来解决[核心问题]。

对于问题一，[简述方法]，得到[关键结果]。

对于问题二，[简述方法]，得到[关键结果]。

对于问题三，[简述方法]，得到[关键结果]。

最后，通过[灵敏度分析/对比验证]验证了模型的[稳定性/有效性]。
结果表明[最终结论]。

关键词：[3-5个]
```

**摘要坑**：
- ❌ 不要写"本文具有重要的现实意义"——这是空话
- ❌ 不要超过一页
- ❌ 不要在摘要里放图表
- ❌ 不要用"我们"——用"本文"
- ✅ 关键结果必须带数值（"误差为3.2%"而非"效果较好"）

### 去 AI 痕迹的具体做法

这是你们 Modex 工作流最关键的一步。AI 生成的文本有这几个特征，逐一清除：

| AI 痕迹 | 表现 | 如何改 |
|---------|------|--------|
| **空洞修饰** | "具有重要的理论意义和广泛的应用前景" | 删掉。改为具体的："该方法将预测误差从 12.3% 降至 3.2%" |
| **模板化结构** | 每段以"首先…其次…最后…"开头 | 打乱顺序，用转折替代 |
| **缺少数据细节** | "结果显示模型表现良好" | 必须带数值："预测准确率达 94.7%，MAE 为 0.032" |
| **句式单一** | 全是"通过…，本文…"的句式 | 长短句交替，穿插设问句 |
| **无自我批判** | 只写优点不写缺点 | 模型评价章节必须写几个真实的局限性 |
| **引用虚空** | "研究表明…""学界普遍认为…" | 不写引用来源的综述句全部删掉 |
| **无数学味** | 缺少公式和符号定义 | 增加 2-3 个核心公式，定义清晰的符号体系 |
| **结论模糊** | "具有一定的参考价值" | 改为："建议…因为…" 带因果链 |

**实操流程**：
1. Modex 生成初稿 → 全文通读，标记所有"闻起来像 AI"的段落
2. 写作手逐段重写——不是改词，是看懂意思后用**自己的话**重新表达
3. 建模手补充公式、符号定义、模型细节
4. 编程手补充数据、图表、具体数值
5. 三人交叉阅读，任何一个人觉得"这段像 AI 写的"就重写

**核心原则**：评审不会因为你用 AI 扣你分，但会因为你的论文"读起来没有人的判断力"而扣分。一篇好的数学建模论文读起来应该像**三个聪明学生在认真讨论一个问题**，而不是一本教科书。

### LaTeX 快速指南

推荐用 Overleaf 在线协作（https://www.overleaf.com），避免本地环境配置问题。

```latex
% 基础模板结构

\usepackage{geometry}
\geometry{left=2.5cm,right=2.5cm,top=2.5cm,bottom=2.5cm}

\usepackage{caption}           % 图注

\usepackage{cite}              % 引用

\title{基于XXX的YYY问题研究}
\author{团队编号：XXXX}
\date{2026年9月}

\begin{document}
\maketitle
\begin{abstract}
摘要内容...
\end{abstract}
\tableofcontents
```

**LaTeX 避坑**：
- 表格用 `booktabs` 包的三线表，不要用默认表格线

- 公式编号统一用 `\label` + `\ref`，不要手写编号
- 参考文献用 BibTeX 管理，格式选 GB/T 7714

## Modex 工作流

### 整体流程

```
赛前准备（现在）
    │
    ▼
拿到题目（比赛第1天 18:00）
    │
    ├──→ 三人读题 + 讨论选题（2h内定题）
    │
    ▼
Modex 生成方案初稿（1-2h）
    │
    ├──→ 建模手：验证模型合理性，修改数学推导
    ├──→ 编程手：验证代码可运行性，修正数据
    ├──→ 写作手：重构论文结构，建立文档框架
    │
    ▼
人工重写（第2天 全天）
    │
    ├──→ 编程手：跑数据 → 输出结果 → 画图
    ├──→ 建模手：修正模型 → 灵敏度分析
    ├──→ 写作手：逐段重写 → 补充数值 → 去AI痕迹
    │
    ▼
交叉验证（第3天 上午）
    │
    ├──→ 三人交换阅读，互相挑刺
    ├──→ 编程手重新跑一遍代码，确认结果不变
    ├──→ 建模手检查所有公式和符号的一致性
    │
    ▼
终稿打磨（第3天 下午）
    │
    ├──→ 摘要：三人一起逐字推敲（最重要！）
    ├──→ 排版：统一图注、参考文献格式
    ├──→ 附录：整理核心代码
    │
    ▼
提交（第3天 20:00 前）
```

### Modex 该做什么、不该做什么

| 可以让 Modex 做的 | 不能让 Modex 做的 |
|-------------------|-------------------|
| 生成论文框架和章节标题 | 写最终版论文正文（痕迹太重） |
| 列出某类模型的几种可选方案 | 选择最终用哪个模型（这是建模手的判断） |
| 生成模型的数学公式（然后人工校验） | 推导全新公式 |
| 生成数据处理的 Python 代码草稿 | 跑实际数据并产出结果 |
| 生成图表的 Python 代码草稿 | 决定用什么图表类型 |
| 检查语法和拼写错误 | 决定论文的叙述逻辑 |
| 翻译英文摘要 | 写中文摘要的核心内容 |

## 常见坑与避雷指南

### 建模坑

| 坑 | 后果 | 正确做法 |
|-----|------|---------|
| 模型越复杂越好 | 评审看不懂，你也解释不清 | 用能解决问题的最简单模型 |
| 只建模型不检验 | 评审认为你对自己的模型没信心 | 灵敏度分析是必须的 |
| 模型假设不明确 | 评审觉得你在瞎建 | 单独列出假设，解释为什么合理 |
| 忽略数据预处理 | 模型结果无意义 | 缺失值、异常值、标准化必须做 |

### 编程坑

| 坑 | 后果 | 正确做法 |
|-----|------|---------|
| 第3天还在 debug | 论文来不及写 | 所有代码必须在第2天跑通 |
| 结果不可复现 | 评审质疑真实性 | 设随机种子，保存中间结果 |
| 图表用默认配色 | 看起来像学生的作业 | 花时间调配色和字体 |
| 代码无注释 | 评审跳过大段代码 | 关键步骤写注释 |

### 写作坑

| 坑 | 后果 | 正确做法 |
|-----|------|---------|
| 摘要空洞 | 评审直接跳过低分 | 带数值！带数值！带数值！ |
| AI 痕迹重 | 2026年起评审会特别注意 | 逐段人工重写 |
| 格式不统一 | 看起来不专业 | 一人负责终审所有格式 |
| 参考文献太少或太旧 | 显得文献调研不够 | 10-15 篇，近 3 年的为主 |
| 附录代码全贴 | 破坏论文结构 | 只放核心算法 |

## 速查表

### 模型选择决策树

```
拿到题目 →
│
├─ 需要排序/评价/选最优？
│   └─ 有主观因素？→ AHP
│   └─ 全是数据？→ 熵权法 + TOPSIS
│
├─ 需要预测？
│   └─ 数据少（<10个点）？→ 灰色预测 GM(1,1)
│   └─ 数据多（>30个点）、平稳？→ ARIMA
│   └─ 有影响因素数据？→ 回归分析
│
├─ 需要优化/分配？
│   └─ 线性、精确解？→ 线性规划/整数规划（pulp）
│   └─ 非线性/NP-hard？→ 遗传算法/粒子群
│
├─ 需要分类/分组？
│   └─ 有标签？→ 判别分析
│   └─ 无标签？→ K-means 聚类
│
├─ 需要降维/找主要因素？
│   └─ 主成分分析（PCA）
│
├─ 有图/网络？
│   └─ 最短路径/网络流/最小生成树
│
└─ 需要分析相关性/差异？
    └─ Pearson 相关 + t检验
```
